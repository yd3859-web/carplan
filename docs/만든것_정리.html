1 · 로그인 실제 폰에서 확인 필요

어떻게 돌아가나

  1. 앱을 켠 첫 순간에 Firebase 익명 로그인이 자동으로 되고 "나만" 그룹이 생긴다. 그래서 로그인 없이도 바로 쓸 수 있다.
  2. 첫 화면(login/Login.kt)에 [구글로 시작하기] [나중에 할게요]. (카카오는 시연에 필요 없어 뺌)
  3. 구글: 안드로이드 Credential Manager로 계정을 고르면, 그 구글 계정을 지금 익명 계정에 연결한다. uid가 그대로여서 그룹·일정·기록이 전부 유지된다. 그 구글 계정이 이미 다른 데이터를 가진 경우에만 그 계정으로 들어가고 화면을 다시 시작한다.
  4. 로그인 뒤 이름 확인 창(구글 이름이 기본, 고칠 수 있음). [나중에]는 다음 실행부터 안 묻고 설정 탭 [연결]로 언제든.

Pleos 에뮬레이터엔 구글 서비스가 없어서 구글 버튼은 "이 기기에 구글 계정이 없어요" 안내만 나온다.

3 · 여행 만들기 · 레일 타임라인 에뮬 확인

여행 하나 = 여러 날 + 날짜별 장소 칸. 한 날의 화면이 레일(trip/TripDayScreen.kt, ui/Rail.kt).

노드 = 장소지난 칸 ✓ 회색(레일 채워짐) · 다음 칸 파랑(느린 후광) · 계획 칸 빈 고리 · 레일 끝 [+]
노드 옆 상자시간(없으면 예상 도착을 회색으로: 앞 칸 + 머무는 60분 + 이동, 누르면 확정) + 장소 + 메모
노드 아래 말풍선칸마다 코멘트 글타래(days/{날짜}/comments, stopId로 연결). 짤 때도, 이동 중에도
노드 사이 점선"이동 약 ○분" — 카카오모빌리티 길찾기(키 있음) / 직선거리×1.3, 40km/h(없음)

편집: 장소 추가(카카오 키워드 검색 → 이름·좌표·주소 저장), 시간, 메모, 빼기(진짜 안 지우고 deleted → 되살리기), 끌어서 순서, [동선 최소로 정렬](사용자가 누를 때만), 근처 추천(카페·맛집·관광지 — 카카오 카테고리 검색). 저장 버튼 없이 바로바로. 바꾸면 그날 version +1 → 차가 이걸 보고 10장으로 이어진다. 칸마다 "○○님이 방금 수정" 표시(updatedBy).

잠금: 운전자 폰은 차가 주행 중(cars.state.drivingRestricted)이면 추가·빼기·끌기·코멘트가 숨고 "운전 중이라 편집이 잠겼어요" 띠.

5 · 6 · 투표 · 다트 에뮬 미확인

투표 (vote/VoteDartSheets.kt, VoteRepository): 질문("점심 뭐 먹지?") + 후보 2~5개(후보마다 [장소]로 검색). 멤버가 한 칸씩 고르고(다시 고르면 바뀜), 과반이면 자동 마감, 과반 없이 전원이 찍으면 최다 득표, 동점은 둘 다 남김, 그룹장·만든 사람은 [지금 마감]. 당선 후보가 장소면 [칸으로] → 그날 레일에 추가.

다트 (DartRepository, Regions.kt): 범위 전국 / 내 위치 10·30·50·100·200km(Q56, 차는 내비 위치) / 지역(시·도) → 바늘이 도는 판 → 동네 이름 + "n번째 다트! · 누가". 다트 방(groups/{gid}/darts)이라 그룹 전원 폰·차 화면에 같은 결과가 실시간으로. 차에서는 주차 중만. 차 결과 카드(Q57): [맛집][카페][관광지] → 누를 때 카카오 1번(그 동네 2km 안 4곳) → 고르면 오늘 칸으로, [이 동네 그대로 넣기]도. 동네 목록은 전국 읍·면·동 3,559곳(assets/regions.csv, 행정동 경계 데이터의 중심점).

8 · 9 · 차 화면 · "다음 목적지로 갈까요?" 에뮬 확인

주행 중(Pleos 주행 제한): "오늘" 한 화면만 — 상태 띠(연료·주유 필요·주행가능·그룹·[말하기]) + 오늘 레일(다음·그다음만) + 가는 곳·남은 거리·도착 시각·진행 막대. 버튼은 숨고 [말하기]와 질문 버튼만. 주차 중: 화면 아래 가운데 둥근 탭 바(넷플릭스 하단 바 참고, 화면과 같은 색, 옆으로 미끄러지는 전환)로 5칸.

캘린더월 보기(칸마다 일정 이름 3개 + 카테고리 색 막대, 폰과 같은 색, 시연용 시험 출근은 안 띄움) + 고른 날 일정 목록 + [이 날 일정 추가] + 오늘 장소는 [안내]

칸 편집(CarTripEdit.kt, 주차 중): 장소 찾기(카카오 1번, 없으면 이름만) → 맨 뒤에 넣기, 칸 눌러 도착 시간(6~22시·30분·없음), [위]/[아래](미끄러지며 자리 바꿈), [빼기] → [되살리기]. 바꾸면 그날 version +1 → 10장으로.

질문이 나오는 때: 차 앱 켜질 때 오늘 칸이 남아 있으면 / 기어 P → D / [더보기]→[다음 목적지 다시 묻기]. 질문은 show() 줄로 한 번에 하나, 우선순위대로. 주차 중엔 레일의 그 장소 아래에서 펼쳐서 묻는다("여기로 갈까요? · 지금 출발하면 hh:mm 도착 · [가기][나중에]", 0.3초), 주행 중·경로 바뀜·주차장·픽업·출근 질문은 위 띠. 흐름:

  1. TTS로 묻고 말이 끝나면 STT로 듣기(동시에 켜면 TTS가 막혀서 순서대로). 못 알아들으면 1번 더, 그 뒤엔 버튼만.
  2. "응"/[가기] → 남은 칸 중 앞 3곳을 경유지 2개 + 목적지로 내비에(SDK가 경유지 이름을 첫째·둘째만 주기 때문). 칸은 개수 제한 없이 등록하고 하나 도착할 때마다 다음 칸을 채운다. 내비에 든 곳은 한 목록(inNavi: 칸·픽업·주유소·들른 곳)으로 관리.
  3. 내비 도착 신호마다 그 칸 visited=true → 폰 레일이 ✓로. 다 돌면 그날 status=DONE, 차 화면 "오늘 일정 끝 · n곳 다녀왔어요(· n곳 건너뜀)".
  4. 좌표 없는 칸(이름만)은 내비 검색 화면으로. 내비는 운전자가 [안내 시작]·[내비 보기]를 눌렀을 때만 앞으로(경로 바꾸기·채우기·주유소는 carplan 화면 그대로).

음성 명령([말하기], 주행 중에도): "주유소/충전소", "주차장", "맛집", "다음 어디야", "건너뛰기", "원래대로", "안내 시작"(VoiceCommand, 테스트 있음). 못 알아들으면 버튼 5개.

찾기: [주유소·충전소][주차장][맛집] → 카카오(주유소는 오피넷) 1번 → carplan 안 목록 → 고르면 다음 경유지 + 레일 "다음"에 표시.

에뮬레이터는 GPS로 차가 안 움직여서 시연 메뉴 시뮬레이션(20장)으로 도착을 흉내 낸다. 에뮬 TTS는 "끝났다" 신호가 안 와서 문장 길이만큼 기다렸다가 듣기로 넘어간다.

10 · 일정 변경 → 내비 갱신 에뮬 확인

  1. 동승자가 폰(또는 차 칸 편집)에서 칸을 빼거나/넣거나/바꾸거나/순서를 바꾼다 → 그날 version +1.

  3. 앞쪽이 바뀌면 묻지 않고 바로 내비 경로를 바꾸고 말해 준다("○○님이 △△를 뺐어요. 경로를 바꿨어요") + 띠에 [원래대로] 10초 (Q23·Q24, 10/31 바꿈).
  4. [원래대로] → 내비만 옛 경로, holdByDriver → 폰에 "운전자가 이전 경로 유지". 반영되면 routeSyncedVersion·etaNext → 폰에 "차에 반영됨 · 다음 도착 12:11".
  5. 건너뛰기(음성 "건너뛰기")는 Stop.skipped로 따로 센다(다녀옴과 구분).

11 · 픽업 에뮬 미확인

  1. 동승자가 레일 [픽업]에서 내 픽업 장소 저장(days/{날짜}/pickups/{uid}). 지도(OSM 타일 ui/SimpleMap.kt)에 차·픽업·나·첫 칸 점.
  2. 차가 출발 질문 대신 "○○ 태우러 가요. 위치를 일행에게 보여 줄까요?" [네, 출발] [공유 없이 출발]. 픽업 장소가 경유지 맨 앞에 들어간다(3곳 규칙 안에서).
  3. 태울 사람이 2명 이상이면 차가 카카오모빌리티 길찾기로 "차 → 픽업들 → 첫 칸" 총 시간이 가장 짧은 순서로 바꿔 저장(키 없으면 직선거리).
  4. 공유 중엔 차가 5초마다 위치를 cars.state.lat/lng에, 30초마다 첫 픽업까지 ETA를 etaSeconds에. 폰 지도엔 차→내 장소 경로선(카카오 도로 좌표)과 "차가 약 n분 뒤 도착 · n.n km".
  5. 픽업 장소 도착 → 그 사람에게 푸시 "차가 도착했어요" → [탔어요] 또는 10분 → 끝. 다 태우면 공유를 끄고 위치를 지운다(이력 안 남김).

12 · 주유 · 충전 · 주차 에뮬 확인(연료차 시험값)

차가 연료(안드로이드 표준 FUEL_LEVEL; 에뮬은 전기차라 배터리)와 주행가능거리를 계속 본다. 연료·주차장은 질문 대신 말하기 + 버튼 하나(차 화면 원칙).

무엇어떻게
오늘 사용량 한 줄 (항상)오늘 화면 제목 아래: 출발 전 "남은 길 약 n km · 연료 약 n% 써요"(직선×1.3, API 없음), [가기] 뒤 도로 거리로 "… · 도착 때 n%" 또는 "중간에 넣어야 해요"
주유하기 임시 칸일정 사이 기름이 모자라는 곳(여유 30km)에 레일 회색 "주유하기 · 임시" 칸 + [최저가 주유소 찾기] → 가는 길 3곳 오피넷 → "가는 길 최저가 주유소" 목록(○○ 지나서/곧) → 고르면 경유지, 칸이 "주유 · ○○ · 경유지로 넣었어요"로, 주유소 도착하면 사라짐. 전기차는 충전하기·충전소
출발 때 주유 계획 (Q55)[가기] 뒤 도로 거리 합 vs 주행가능거리. 모자라거나 연료 50% 이하일 때만(85%에선 안 넣음): 50% 되는 지점~모자라기 전 구간 3곳(곧·중간·직전)에서 오피넷, 3km 안, 최저가(10원 차이면 뒤쪽) → "○○ 지나서 연료 17%쯤일 때 △△에서 넣으면 가장 싸요. 리터당 1,824원" + 레일 "추천 주유" 칸 [경유지로]. 10km마다 조회는 안 함(API 한도)
안내 없을 때연료 ≤ 설정 기준(기본 20%, cars.fuelAlertPercent)이면 상태 띠 "주유 필요"
주차장다음 칸 5분 전 말해 주기 + [근처 주차장 찾기], 운전자 아닌 멤버 폰엔 "주차장 찾아봐 주세요" 푸시

13 · 14 · P단 → 기록 칸 · 기록 탭 · 내보내기 일부 에뮬 확인 · 사진 업로드 403(규칙 배포 필요)

시동 상태는 앱이 못 받아서(확인됨) 차가 주는 신호 여러 개로 "사람이 내렸다"를 판단한다.

  1. 기어 P → "섰다" 후보. P 상태에서 운전석 문이 열리면 바로 도착 확정(신호등은 자동으로 걸러짐). 문 신호 없이 P만 계속이면 5분 뒤 확정.
  2. 운전석은 그대로고 다른 자리 문·착석만 바뀌면 칸을 안 만든다(내려 주기·태우기).
  3. 현재 위치를 읽어 일정 칸 300m 안이면 그 칸에 연결, 아니면 카카오로 장소 이름을 찾아 계획 밖 칸(휴게소 등). 여행 없는 날이면 나만 그룹에 "일상 기록"(log-날짜) 일정이 자동으로 생기고 그 밑에 칸.
  4. 기록 칸(days/{날짜}/records: 장소·도착·떠난 시각·사진·한 줄) 생성 → 그룹 전원 푸시 "○○ 도착! 사진이랑 한 줄". P → D 되면 떠난 시각.
  5. 주유소면 15장 "주유했어요?"로 이어진다.

폰: 레일 안에 기록 칸이 같은 그림으로 채워진다(계획 밖은 다른 모양, 이동 줄엔 실제 걸린 시간). 사진은 칸당 10장, 긴 변 1600px로 줄여 Firebase Storage(Blaze 뒤). 장소 이름이 틀리면 "장소 바꾸기". 기록 탭은 날짜별 모음. 차 기록 탭(10/31): 달력(기록 있는 날 굵게 + 여행 파랑/일상 회색, 사진 있으면 그날 첫 사진) + 고른 날 레일(✓ 노드, 사진·한 줄 큰 글씨·친구 코멘트 이름 말풍선이 주인공, 시각·머문 시간·주차·이동은 작게), 반반에선 위로 밀면 달력이 접힘. 보기만(사진·한 줄은 폰). 기록 칸에 주차 위치(parkedLat/Lng, 폰에서 "B2 C-14" 같은 parkingNote). 내보내기 = 하루를 세로 긴 이미지 1장(칸마다 대표 사진·장소·시간·한 줄) 또는 짧은 영상(사진 슬라이드 2.5초씩 + 장소·시간 자막, mp4) → 공유 시트.

15 · 차량 관리 에뮬 미확인

항목 7개: 주유 · 점검 · 공기압 · 엔진오일 · 타이어 교체 · 세차 · 보험 갱신. 폰 차량 탭(car/CarTab.kt) = 차 상태 줄 + 이번 달 주유비 + 항목별 마지막 기록·다음 예정·[주기]·[기록].

  • 다음 예정 = km 주기와 날짜 주기 중 먼저 오는 쪽(MaintenanceRules). km는 차가 1분마다 올리는 주행거리(Odometer)로, 하루 평균을 모르면 40km/일로 날짜 환산. 기본 주기: 엔진오일 1만km·1년, 점검 1.5만km·1년, 공기압 1달, 타이어 5만km, 세차 2주, 보험은 갱신일 직접. 항목별로 고칠 수 있음(cars.intervals).
  • 기록하면 나만 그룹에 차량 관리 일정 + due-항목 예정 일정이 생겨 캘린더와 오늘 헤더에 뜬다. 예정 7일 안이면 아침 9시 푸시(Functions).
  • 차 차량 탭(10/31): 상태 4칸 + 항목별 "n일 남음/지남" + [했어요](오늘·차 주행거리). 금액·주기는 폰.
  • "주유했어요?": P단 정차 중 연료가 5%p 이상 오르면 차가 묻고, 예 → 주유 기록 자동(주행거리 포함, 금액·리터는 폰에서 나중에).

16 · 출퇴근 에뮬 미확인

출퇴근 카테고리로 반복 일정(요일 + 시간 + 장소)을 등록하면(Repeat.kt), 차 앱이 그 시간 ±60분 안에 켜지거나 P→D일 때 "회사로 갈까요?" → 응 → 내비. 한 번 "아니"면 그날은 다시 안 묻고, 오늘 여행이 있으면 여행 질문이 먼저. 학습(Commute.kt): 기록 칸을 보고 같은 요일·비슷한 시간(±60분)에 같은 곳(300m 안)이 3번이면 캘린더 위에 "출근 일정으로 등록할까요?" 띠. 묻지 않고 자동 등록은 안 함.

17 · 알림 배포됨

푸시는 서버에서 보내야 해서 Cloud Functions(functions/index.js, asia-northeast3)가 Firestore 변화를 보고 FCM으로 보낸다. 폰은 첫 실행에 알림 권한을 묻고 토큰을 users/{uid}.fcmTokens에 둔다. 알림을 누르면 carplan://trip/그룹/일정/날짜로 그날 레일이 열린다.

언제누구에게트리거
일정 칸 뺌(추가·순서는 화면만)뺀 사람 빼고 그룹 전원onStopRemoved
투표 열림 / 마감만든 사람 빼고 전원 / 전원onVoteWritten
도착 → 기록 칸 생김그룹 전원onRecordCreated
픽업 차 곧 도착(3분 안) / 도착그 동승자onPickupWritten
