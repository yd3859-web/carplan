## 1. 무엇을 만드나 (작동시나리오 3장 그대로)
1. 일정 만들기에서 카테고리 **여행**을 고르면 → 여행 만들기 흐름으로 간다. 원래는 그룹을 고르거나 새로 만드는데, **그룹(4장)은 아직 없으니 이번엔 나만 그룹에 만든다.** 4장에서 "그룹 고르기"를 붙일 자리만 남긴다.
2. **날짜 고르기**: 여러 날 가능(Q04 정함). 캘린더에는 이어진 막대 하나로 보이고, 날짜를 누르면 **그날 일정(장소 칸 목록)**이 따로 보인다.
3. 그날에 **장소 칸 추가**: 한 칸 = **장소(필수) + 시간(선택) + 메모(선택)**.
   - 장소는 **카카오 로컬 키워드 검색**으로 고른다(이름·좌표·주소·kakaoId 저장). 폰엔 내비가 없어서 카카오.
4. **칸 순서는 끌어서 바꾸기.** 이 순서가 그대로 내비 경유지 순서다.
   - **[동선 최소로 정렬]** 버튼은 사용자가 누를 때만 적용(강제 안 함, 정함). 칸 사이 시간은 카카오모빌리티 길찾기.
5. **근처 추천**: 카페·맛집·관광지 버튼 → 현재 위치 또는 앞 칸 장소 기준 카카오 카테고리 검색 → 골라서 칸 추가(정함).
6. **모두가 편집**(차주가 호스트, 일행도 같은 권한 — Q17). 저장 버튼 없이 바로 저장, Firestore 실시간 반영.
   - 칸을 빼면 진짜 지우지 않고 `deleted = true` (되살리기·알림 문구용).
   - "○○님이 △△를 뺐어요" 푸시는 17장(FCM, Cloud Functions)에서. 이번엔 화면 표시까지만.

## 3. 데이터 (이미 shared에 있음 — 바꾸면 18장도 같이)
- 여행 = `groups/{gid}/events/{eid}` 의 `Event(categoryId = "trip", startDate, endDate, carId?, driverUid?)`
- 하루 = `.../events/{eid}/days/{yyyy-MM-dd}` → `TripDay(version, currentStopIndex, status)`
- 장소 칸 = `.../days/{date}/stops/{id}` → `Stop(order, place: Place, time?, memo, createdBy, deleted, visited)`
- 경로는 `FirestorePaths.day / stops` 를 쓴다(문자열 직접 쓰지 말 것).
- **칸이 바뀔 때마다 그 날의 `TripDay.version`을 +1** (차가 무엇이 새로운지 알게 — 10장에서 씀). 예전 `TripRepository.addStop`이 batch로 이걸 했었다(커밋 47d9f66에서 삭제, `git show 4131061:shared/src/main/java/com/htb/carplan/shared/data/TripRepository.kt` 참고).
