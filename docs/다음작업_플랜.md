흐름은 다 있음: 픽업 장소 등록(`PickupSheet`) → 출발 때 "태우러 가요, 위치 보여 줄까요?"(`askPickup`) → 경유지 맨 앞·2명 이상이면 총 시간 순(`routeWithPickups`) → 5초마다 차 위치(`startSharing`) → 30초마다 ETA(`startEtaLoop`, 내비 값, 없으면 카카오 5분에 한 번) → 폰 지도 차 점·경로선·"약 n분 · x km" → 도착·[탔어요]·10분 뒤 끝 → 공유 끔 → Functions "곧 도착" 푸시.

| 우선 | 문제 | 왜 생기나 | 사용자가 겪는 것 | 고칠 곳 |
|---|---|---|---|---|
| **P1 (최우선, 한 줄)** | 차 위치가 계속 지워짐 | `CarRepository.updateState`가 `state.lat/lng`도 같이 씀 → `VehicleMonitor`는 위치를 안 넣어 늘 null → 주행 중 연료·주행거리·기어가 바뀔 때마다(1초 묶음) 위치가 지워지고 5초 뒤 공유 루프가 다시 채움 | 동승자 폰 지도에서 차 점·"약 n분" 글자가 깜빡이거나 사라짐. 위치가 비면 폰의 경로선 기억(`pathFrom`)도 지워져 다시 나타날 때마다 **카카오 길찾기 재호출**(API 낭비) | `updateState`에서 `state.lat`·`state.lng` 빼기(위치는 `updateLocation`만 씀) |
| **P2** | 차 앱이 다시 켜지면 공유가 안 이어짐 | 공유 루프는 픽업 질문 "응"일 때만 시작. 재시작 뒤엔 서버에 `pickupSharing = true`가 남아 질문을 건너뜀 → 루프 없음 | 폰엔 "차가 오는 중"인데 차 점이 멈춘 자리에 그대로 | `TripNavigator`: 오늘 여행에 `pickupSharing == true` + 기다리는 사람 있음 → `startSharing` 다시 켜기 |
| P3 | 칸 없이 픽업만 있으면 앱 켤 때 안 물음 | 시작 질문(`askedOnStart`)이 `t.next != null`일 때만 | 앱 켜도 조용함(P→D·버튼으로는 물음) | 조건에 `waitingPickups.isNotEmpty()` 추가 |
| P4 (폰, 뒤로) | 폰 남은 시간이 500m마다만 바뀜 | 폰이 받은 카카오 경로 시간을 차 ETA보다 먼저 씀, 경로는 500m 움직여야 다시 받음 | "약 7분"이 한동안 그대로 | 남은 시간은 차 `etaSeconds` 먼저, 경로선만 500m마다 |

같이 볼 것: P1을 고치면 다트 "내 위치 N km"(Q56)의 차 위치는 여전히 비어 있음 → 다트는 `TripNavigator.lastLocation`을 직접 써야 함(Q56 3번).
